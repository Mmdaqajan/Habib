# حبیب (Habib)

حبیب یک اپلیکیشن شخصی برای ثبت راحت عادت‌هاست. هدف اصلی آن کمک به ساختن عادت‌های جدید و بهترکردن تدریجی عادت‌های فعلی است؛ مثلاً افزایش آرام زمان مطالعه یا منظم‌ترکردن ورزش. ثبت روزانه باید ساده باشد تا خود پیگیری عادت به کار اضافه و خسته‌کننده‌ای تبدیل نشود.

## تصمیم‌های اصلی محصول

- **ثبت راحت عادت‌ها اولویت دارد:** کاربر باید بتواند با کمترین مراحل عادت روزانه‌اش را ثبت کند.
- **کمک به رشد تدریجی:** برنامه باید به ساخت عادت جدید یا بهترکردن عادت جاری، یک قدم در هر بار، کمک کند؛ نه اینکه با هدف‌های سنگین به کاربر فشار بیاورد.
- **استفادهٔ شخصی:** حبیب فعلاً برای استفادهٔ شخصی ساخته می‌شود، نه برای حساب‌های متعدد یا یک سرویس اجتماعی.
- **آفلاین در اولویت است:** اطلاعات باید تا جای ممکن روی دستگاه و بدون وابستگی به اینترنت در دسترس باشند. اینترنت یا سرور برای استفادهٔ روزمره هدف فعلی نیست.
- **سادگی و حریم خصوصی:** قابلیت‌های تازه نباید ثبت روزانه را پیچیده کنند یا بدون نیاز داده‌های شخصی را به سرویس بیرونی بفرستند.

## حبیب چه کمکی می‌کند؟

- عادت‌های دلخواهت را بساز و برایشان عنوان، توضیح و ایموجی بگذار.
- عادت‌ها را به دو شکل پیگیری کن:
  - **تیک‌زدنی:** مثل ورزش یا مرتب‌کردن اتاق.
  - **عددی:** مثل مطالعه برحسب صفحه یا ورزش برحسب دقیقه، همراه با واحد و بازهٔ هدف.
- پیشرفت روزانه و روند عادت‌های عددی را در نمودار ببین.
- تقویم فعالیت و خلاصهٔ عادت‌های انجام‌شده را بررسی کن.
- یادآوری‌های روزانه، هفتگی، ماهانه و سالانه ثبت کن.
- اطلاعات پروفایل را نگه‌دار.

حبیب برای سرزنش‌کردن یا ایجاد فشار طراحی نشده؛ هدفش کمک به دیدن روند و ادامه‌دادن با قدم‌های کوچک است.

## محصول موردنظر

محصول حبیب یک **اپلیکیشن موبایل شخصی و آفلاین** است. نسخهٔ Android برنامهٔ اصلی برای استفادهٔ روزمره است؛ قرار نیست نسخهٔ وب به‌عنوان محصول جداگانه ارائه شود.

### کد Django موجود در مخزن

کد Django و قالب‌های وب موجود، **نمونهٔ اولیه و مرجع توسعهٔ اپ موبایل** هستند؛ برای بررسی ایده‌ها و رفتارهای اولیهٔ عادت‌ها به کار می‌آیند. این کد به معنی برنامه‌ریزی برای انتشار یا نگهداری یک محصول وب نیست. کاربر نهایی برای استفاده از اپ Android به اجرای Django، مرورگر، سرور یا اینترنت نیاز ندارد.

### اپ Android آفلاین

نسخهٔ بومی اندروید در پوشهٔ `android/` قرار دارد و فایل نصب آن در `apk/habib-mobile-debug.apk` ساخته می‌شود. این نسخه عادت‌ها، ثبت‌های روزانه، یادآوری‌ها و پروفایل را روی همان گوشی ذخیره می‌کند. اطلاعات پروفایل شامل نام، تاریخ تولد شمسی، ایمیل، تلفن و تصویر است؛ سن محاسبه می‌شود و در روز تولد هر سال اعلان محلی فرستاده می‌شود. عادت‌های عددی حداقل و حداکثر دارند و با دکمه‌های کم‌وزیاد قابل ثبت‌اند؛ نمودار عادت انتخاب‌شده نیز با همان بازه مقیاس‌بندی می‌شود. تقویم یادآوری‌ها فارسی است، برای روزها می‌توان رویداد رنگی ثبت کرد و یادآوری‌ها را می‌توان با فیلترهای کنارهم پالایش کرد. لمس هر یادآوری امکان ویرایش یا حذف آن را می‌دهد.

اطلاعات در پایگاه دادهٔ محلی گوشی ذخیره می‌شوند و برای کار روزمره به سرور یا اینترنت وابسته نیستند. می‌توان یک اعلان دلخواه را برای چند دقیقهٔ بعد زمان‌بندی کرد؛ یادآوری تولد نیز هر سال ساعت ۹ صبح تنظیم می‌شود. برای دریافت اعلان‌ها باید مجوز اعلان گوشی فعال باشد. یادآوری‌های تکرارشوندهٔ عادی (روزانه، هفتگی، ماهانه و سالانه) هنوز به‌طور خودکار اعلان زمان‌بندی نمی‌کنند.

### ساخت و نصب نسخهٔ Android

پیش‌نیاز ساخت:

- JDK 17
- Android SDK Platform 35 و Build Tools 35
- Gradle Wrapper همراه مخزن (Gradle 8.11.1)

در Windows PowerShell از ریشهٔ مخزن، APK آزمایشی را بساز:

```powershell
.\android\gradlew.bat -p .\android copyDebugApk
```

فایل خروجی در `apk/habib-mobile-debug.apk` ساخته می‌شود. برای بررسی کیفیت کد Android:

```powershell
.\android\gradlew.bat -p .\android lintDebug
```

برای نصب، APK را به گوشی Android 8.0 (API 26) یا بالاتر منتقل و باز کن؛ اگر خواسته شد، اجازهٔ نصب برنامه از منبع انتخاب‌شده را فعال کن. برای دریافت اعلان‌ها نیز مجوز اعلان برنامه را بپذیر. داده‌ها فقط روی همان گوشی ذخیره می‌شوند و پس از حذف برنامه قابل بازیابی نیستند.

APK ساخته‌شده debug و با کلید توسعه امضا شده است؛ برای انتشار عمومی یا Google Play، نسخهٔ release با کلید امضای اختصاصی بساز. ترجیحاً APK انتشار را به‌عنوان فایل GitHub Release قرار بده و نه در تاریخچهٔ Git؛ سورس Android و دستور ساخت آن در مخزن باقی می‌مانند.

## محدودیت‌های فعلی

- یادآوری‌های تکرارشوندهٔ عادی هنوز اعلان خودکار سیستم‌عامل ندارند؛ اعلان یک‌باره و یادآوری سالانهٔ تولد در دسترس‌اند. زمان‌بندی از نوع غیر دقیق است و ممکن است Android آن را به‌دلیل حالت صرفه‌جویی باتری کمی به تأخیر بیندازد.
- کد Django نمونهٔ اولیه است و همگام‌سازی آن با اپ Android جزو هدف فعلی نیست.
- رابط و اعلان‌ها باید روی دستگاه‌های واقعی و نسخه‌های مختلف Android نیز آزمایش شوند؛ در حال حاضر بررسی ساخت و lint انجام می‌شود.
